# 14.0 — Guard rails

Spec: [`../email-identity.md`](../email-identity.md). Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Land the three doors as failing assertions before anything is fixed, so
the detector is proven rather than assumed.

Into `tests/identity/run-contract-tests.php` for the unit-level rules, and
`tests/integration/run-provider-gates.php` for the three doors themselves. The
split is not tidiness: the doors are only meaningful against a real WordPress. A
stubbed `authenticate` chain cannot show that core resolves `user_email` at
priority 20 while the plugin resolves the directory at 30, and that disagreement
is the whole phase.

## Files

- `tests/identity/run-contract-tests.php`
- `tests/integration/run-provider-gates.php`
- No production file is touched.

## Steps

Five rules. Rules 1–3 are the doors; 4–5 are the invariants that keep the fix from
being undone.

1. **A provider-first account is reachable by its own address.** Provision one
   through `AccountProvisioner` with a verified email, then drive the identify
   step with that address. It must reach the password screen, not the registration
   OTP branch. Fails today at `class-form-controller.php:344`.

2. **Recovery agrees with existence.** `PasswordResetHandler::start()` on the same
   address must not answer `smart_login_unknown_identity`. Fails today at
   `class-password-reset-handler.php:87`.

3. **No door spends an OTP it cannot honour.** Driving the identify step must not
   issue a code for an address that `wp_users` already holds. Asserted on the OTP
   table, not on the returned array — the point is what was written, not what was
   reported. Fails today: a code is issued and the flow walks two more steps
   before refusing.

4. **One writer for a verified email.** No file outside `UserManager` may pair a
   `user_email` write with a `META_EMAIL_VERIFIED` write. Structural, tokenised —
   not a regex, for the reason 11.0's rule 1 gives. **Reports PENDING until 14.2
   exists**: a rule naming a function that has not been written yet passes for want
   of a subject, and 10.0 and 11.0 both made that mistake before it was written
   down.

5. **Proof is required to reach the directory.** Every call that links an `email`
   channel row must pass a `VerifiedClaim`. This one **passes today** and must keep
   passing — it is the property that stops 14.2 becoming a way to mint identities,
   and a rule arriving beside the feature it guards cannot catch that feature
   breaking it. Same argument as 13.0's rule 4.

## Acceptance

Rules 1, 2 and 3 fail. Rule 4 reports PENDING. Rule 5 passes.

`php tests/run-all.php` — no other suite moves, checked against a worktree of the
current `HEAD` rather than from memory.

The integration gate is run on the real site, and a BLOCKED gate is not a pass —
10.3 shipped with its tracker row unticked for exactly this and the same rule
applies here.
