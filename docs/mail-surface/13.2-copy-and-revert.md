# 13.2 — Copy to edit, and the way back

Spec: [`../mail-surface.md`](../mail-surface.md) (D3). Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Let an administrator start from the shipped wording instead of a blank
box, without that being the end of inheritance.

## The tension, stated before the feature

11.4 established that an empty override box shows what it will actually send, so
blank reads as *inheriting this* rather than *this email has no subject*. That is
what keeps one wording in one place for a site that never customises.

A **Chép mẫu để sửa** button fills the box. A filled box has stopped inheriting.
Pressed on all six messages — which is what a tidy-minded administrator does on
first sight — it produces six copies of text that used to live once, and a later
change to the shared pair reaches none of them.

The button is still right: typing a template from nothing is worse. But it is
only right **in a pair**, and the pair is the whole of this sub-phase:

| Control | Does | Leaves the box |
| --- | --- | --- |
| Chép mẫu để sửa | writes the resolved text into the field | overriding |
| Xoá, dùng lại mẫu chung | empties the field | inheriting |

## Files

- `includes/Admin/class-field-renderer.php`
- `assets/js/admin.js`, `assets/css/admin.css`
- `tests/mail/run-template-tests.php`

## Steps

1. **Both controls, always, on every template field.** Not one that toggles: a
   toggle has a state, the state has to be read from whether the box is empty,
   and a box the administrator emptied by hand would then offer the wrong label.
   Two buttons have no state.

2. **The copy source is `MailRegistry::resolve()`**, the same call the transport
   makes and the same one the placeholder already shows. Copying anything else —
   the row default, say — would put text in the box that differs from what the
   message was sending a second earlier.

3. **The resolved text travels in a data attribute**, already rendered for the
   placeholder. No AJAX: the value is on the page because it is the placeholder,
   and a round trip to fetch what is already in the DOM is a round trip that can
   fail.

4. **Revert clears; it does not restore a previous override.** Undo is the
   browser's job inside a textarea, and a plugin-level undo stack for a field
   with a Save button below it is a promise this cannot keep across a reload.

## Acceptance

Rule 3 green: every copy affordance is matched by a revert affordance, counted
rather than eyeballed.

The copied text equals `MailRegistry::resolve()` for that message and part —
asserted against the resolver, not against the row default, because those differ
exactly when the shared pair has been edited, which is the case that matters.

A field cleared through revert stores empty and resolves back to the shared pair,
which is the round trip 11.1 already asserts and this must not break.

## Not in scope

A preview of the rendered message. It belongs with the send-a-test follow-up,
and neither is needed to edit a template.
