# 13.0 — Guard rails

Spec: [`../mail-surface.md`](../mail-surface.md). Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Land the rules red before 13.1–13.3 exist.

Into `tests/mail/run-template-tests.php`, which already owns the layout and the
registry. 12.0 put its rules in an existing suite for the same reason and the
same trade applies: that suite is now `required`, so the branch is red until
13.1 lands.

## Files

- `tests/mail/run-template-tests.php`
- No production file is touched.

## Steps

Four rules.

1. **Every message is reachable from the list.** For each `MailRegistry` row, the
   rendered screen must contain a list entry naming it *and* a panel holding its
   two fields. Guards the generated list against drifting from the generated
   fields — two things built from one array that could still disagree about which
   rows exist.

2. **Hiding a panel does not hide it from the save.** Every message's subject and
   body input must be present in the markup even when its panel is not the open
   one. This is the property that makes D1's JavaScript safe, and it is exactly
   what a later "optimisation" to render only the open panel would break —
   silently, because the fields would simply stop being posted and
   `sanitize()` reads absence as "not on this tab".

3. **Copy-to-edit has a way back.** Any control that fills a template box must be
   accompanied by one that empties it. Asserted as a count: the number of
   copy affordances equals the number of revert affordances. Without this,
   11.4's inheritance dies the first time somebody presses copy on all six.

4. **The structure tokens are opt-in.** A body using neither `{{code_block}}` nor
   `{{button:…}}` renders byte-identically to what it renders today. This is what
   keeps 13.3 from being a migration, and it is the rule most likely to be broken
   by "improving" the default bodies at the same time.

## Acceptance

Rules 1, 2 and 3 fail against today's screen. Rule 4 passes today — nothing uses
the tokens yet — and must keep passing, which is the point of landing it now
rather than with 13.3: a rule that arrives alongside the feature it guards cannot
catch that feature breaking it. Same argument 11.0's rule 6 made.

`php tests/run-all.php` — no other suite moves.

## Not in scope

Any production change.

### The brief was wrong about rule 2

It predicted rules 1, 2 and 3 would fail. Rule 2 passes today: the screen is a
flat form-table, so every input is already present. It is a property to
**preserve**, not one to reach — like rule 4, and for the same reason. Rendering
only the open panel is the obvious optimisation once 13.1 exists, and it would
stop five messages being saved without a visible symptom.

Two of four rules landing green is the right shape for a phase that is mostly
rearranging things that already work. A rule that cannot fail today is still
worth having if the thing it guards is about to be built next to it.

### `ow_capture()` moved into the harness

It lived in `run-admin-tests.php`, and rule 1 needs to render a screen from the
mail suite. Two suites, one helper: it belongs in `tests/harness.php`. A second
copy would have been a second place to forget that it treats a PHP notice as a
failure.

### An environment change looked exactly like a catastrophic regression

`C:\xampp` disappeared mid-session, taking the PHP binary this project's suites
have always run under. Local's PHP works but ships no `php.ini`, so `openssl` is
not loaded — and `SecretBox` needs it.

The first full run after switching binaries reported **twenty failures across
four suites**: provider secrets, captcha configuration, the automation envelope,
the signature, the event bus. Every one of them read as a real defect in code
that had not been touched.

`-d extension=php_openssl.dll` does not fix it, because `run-all.php` spawns each
suite as a child process with no extra flags. `PHPRC` pointing at a directory
with an ini does, because children inherit it. Recorded in project memory,
because the failure presents as a regression in the most alarming possible
places and nothing in the output suggests the environment.
