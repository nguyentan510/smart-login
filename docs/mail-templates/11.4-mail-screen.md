# 11.4 — The mail screen

Spec: [`../mail-templates.md`](../mail-templates.md). Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Somewhere to edit the messages, grouped the way an administrator
thinks about them rather than the way the registry stores them.

Sequenced last, for the reason 10.6 was: a screen can only present a model that
exists.

## Files

- `includes/class-field-registry.php` — the tab and its sections
- `includes/Admin/Screens/class-settings-screen.php` — per-message chrome
- `includes/Admin/class-field-renderer.php` — the token list beside a body
- `assets/css/admin.css`
- `tests/identity/run-admin-tests.php`

## Steps

1. **A second-level tab under Gửi mã**, slug `delivery-mail`, label
   *Nội dung email*. Same constraint as 10.6: it has its own Save button, so it
   is a real tab slug, and it hangs off `delivery` through `tab_parents()`.

   Not a new top-level tab. The strip is at six and the reason 10.6 built a
   second level was to stop it growing.

2. **One section per registry group**, in registry order: *Mặc định* (the shared
   fallback pair), *Mã xác thực* (the four intents), *Cảnh báo quản trị* (the
   two from 11.3), *Giao diện* (the layout settings from 11.2).

3. **Each message states when it fires.** The row's `when` text renders above
   its two fields. An administrator editing "Đặt lại mật khẩu" should not have to
   infer from the label whether it covers a forgotten password, a changed one, or
   both.

4. **The token list sits beside the body it belongs to**, from that row's
   declared set — not the global table currently rendered once under the SMS
   section. That table stays where it is; this is a different list for a
   different reason.

5. **Empty means inherited, and says so.** A blank override renders with a
   placeholder showing the text that will actually be sent, so an empty box reads
   as "using the default" rather than as "this email has no subject".

## Acceptance

Every generated field is drawn by exactly the tab that claims it — the same walk
10.6 added, now covering rows that no human typed.

Saving the mail screen leaves `sms.*`, `email.*` and `automation.*`
byte-identical, and saving the email channel screen leaves the overrides
untouched.

A message with no override shows the inherited text as a placeholder and stores
nothing; typing into it stores an override; clearing it restores inheritance.

The delivery gate renders this screen alongside the other four.

## Not in scope

Preview and send-a-test-of-this-message. Both are worth having and neither is
needed to edit a template; they are a follow-up, recorded here so the absence is
a decision.
