## Steps

Six rules. Each names the sub-phase that turns it green.

1. **Every message the plugin sends comes from the registry.** No `wp_mail()`
   call in `includes/` outside `MailTransport`. Red today: `RateLimiter:267` and
   `CircuitBreaker:163` compose their own. Turns green at 11.3.

2. **Every intent resolves to a template.** For each `AuthAction` intent,
   `MailRegistry` must return a subject and a body — falling back to the shared
   pair is a resolution, being absent is not. Guards D1's fallback against being
   quietly dropped once four overrides exist.

3. **A template may only use tokens its row declares.** Scan every default
   subject and body for `{{token}}` and require each to be in that row's
   allowed set. Catches the failure this phase exists to prevent — a token that
   renders as a silent empty string — in the shipped defaults, before an
   administrator can meet it in their own.

4. **Every declared message is reachable from the screen.** Each registry row's
   generated field paths must appear in `FieldRegistry::all()` and be drawn by
   the tab they claim. The same property the admin suite asserts for hand-written
   fields, applied to generated ones, since generation is exactly where a row can
   go missing without anybody noticing.

5. **The layout wraps once.** With `is_html` on, the rendered message contains
   exactly one layout opening marker. A body that itself contains the marker —
   an administrator pasting a full document — must not produce two. Turns green
   at 11.2.

6. **Plain text never carries markup.** With `is_html` off, the rendered body
   passes `wp_strip_all_tags()` unchanged. `MailTransport` already strips, so
   this pins the behaviour before the layout gives it something to strip.

### This brief was wrong twice, in opposite directions

**Rule 3 would not have "passed vacuously and said so".** That is what this brief
asked for, and it is the mistake 10.0 made with its own rule 5 and had to
correct: a rule that passes because its subject does not exist states the
opposite of the truth. PENDING, with `MailRegistry` named as the blocker.

**Rule 6 is not PENDING.** The brief listed it among the three that would be, but
`MailTransport` already strips tags when `is_html` is off, so the rule can be
asserted today — and should be, because a rule that only arrives alongside the
feature it guards cannot catch that feature breaking it. It passes now and 11.2
has to keep it passing.

Two mistakes in one acceptance paragraph, both about whether a rule has a
subject yet. Worth recording as a pattern rather than as two slips.

### A regex could not express rule 1, and rewording was not available

The first version grepped for `wp_mail(` and flagged four files. Two were text:
`class-field-registry.php:348` has `<code>wp_mail()</code>` in help text, and
`class-webhook-tester.php:191` has a translator string explaining why
`wp_mail()` returned false.

10.3 hit this and fixed it by rewording a docblock, which cost nothing there.
Here it would: naming the function *is* the value of both strings, and
allowlisting their files would silently cover a real call added to either later.

So rule 1 tokenises instead — `token_get_all()`, find `T_STRING` equal to
`wp_mail` whose next non-whitespace token is `(`, skipping anything preceded by
`->`, `::` or `function`. It costs milliseconds and answers the question that
was actually being asked. The two real offenders are the only two reported.
