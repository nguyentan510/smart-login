# 19.6 — The provider round trip

Spec: [`../sign-in-anywhere.md`](../sign-in-anywhere.md), decision 6.
Status: [`../refactor-plan.md`](../refactor-plan.md).

**Goal.** "Tiếp tục với Google" from a product page returns to the product page
— and, for a new account, returns with the popup already open at onboarding.

Sequenced after 19.5 because the return lands in the redirect policy that
sub-phase writes. Shipping it first would mean routing a provider signup at a
destination that does not exist yet.

## Files

- `templates/form-auth.php` — the return url
- `includes/Auth/class-provider-auth-controller.php` — the marker on return
- `assets/js/smart-login-launcher.js` — re-open on the marker

## Steps

1. `form-auth.php:127` calls `ProviderAuthController::start_url( id, $sl_redirect )`
   and `$sl_redirect` comes from `$_GET['redirect_to']` (`:30`) — empty for a
   popup on a product page. In a fragment render it comes from the render
   context 19.2 introduced, so the return url is the host page.
2. `start_url()` already passes it through `wp_validate_redirect()` (`:47`) and
   `start()` re-validates (`:99-101`). Nothing about that changes; the value is
   simply no longer empty.
3. On return, a **new** account gets the flow marker appended to the host page
   URL rather than a redirect to the profile page — the same in-place decision
   19.5 made, reached through the provider path instead of the OTP one.
4. The launcher reads that marker on load, opens the dialog at `onboard`, and
   strips it with `replaceState` so a reload does not reopen the welcome screen.
5. An existing account returns to the host page signed in, with no dialog.

## Acceptance

- A provider login started from a fragment rendered for page *P* has *P* in its
  transaction return url — asserted on the stored transaction, not on the link
- An off-site `page` still resolves to `''`, unchanged
- A new provider account returns to *P* with the marker; an existing one returns
  to *P* without it
- The marker survives exactly one load
- Run against a real WordPress through `tests/integration/` — a provider
  round trip is the shape of thing four gates once missed a fatal in
- Every other suite at its previous count

## Not in scope

`window.open` and `postMessage`. Declined in the spec with its reasons; the
full-page redirect is the decision.
