## Rules

Each one names the finding it comes from.

1. **Parity.** Every step the popup can be opened at resolves to a handler
   reachable over REST. Derived from `Flow::PUBLIC_STEPS` rather than from a
   second list — a rule with its own copy of the allowlist stops testing the
   allowlist. *(Finding 3.)*
2. **One decision, not two.** `FormController` carries no step decision that the
   flow engine does not own. Asserted structurally: the handler bodies delegate,
   they do not branch. *(Decision 2.)*
3. **In place means in place.** A new user authenticated with an in-place
   context is not handed a redirect to `profile_url()`. Behavioural, driven
   through `PostAuthRedirector` with both context shapes. *(Finding 1.)*
4. **No nonce in cacheable markup.** Nothing hooked to `wp_footer` emits
   `RequestGuard::fields()` output. Structural, over the rendered footer.
   *(Finding 5.)*
5. **No duplicate ids.** A page rendering both `[smart_login]` and the popup
   shell yields no repeated `id`, and no more than one `autofocus`.
   *(Finding 9.)*
6. **The shell is outside every form.** The dialog markup contains no `<form>`
   that is nested inside another, and the shell itself is emitted after the last
   `</form>`. *(Finding 9, second half — the bug `DeferredForms` already paid
   for.)*
7. **The fragment does not link into the API.** A fragment rendered with an
   explicit host-page base emits step links and a `redirect_to` belonging to that
   page, never to `/wp-json/`. *(Finding 8.)*
8. **Degradation.** The launcher's anchor rewriting resolves to
   `Flow::login_url()` when a host page exists, and leaves the fragment untouched
   when one does not. *(Decision 4.)*

9. **One vocabulary.** No trigger name exists in JavaScript that PHP does not
   own. The step allowlist and the captured-URL list are both localized from
   `Flow::PUBLIC_STEPS` and `smart_login_capture_links`; a second copy in the
   launcher fails the rule. *(Finding 11 — the defect this rule exists to
   prevent was in the first draft of this plan.)*
10. **No link is rewritten.** Running the launcher over a document leaves every
    `a[href]` byte-identical. *(Decision 8 — the property the capture's entire
    safety argument rests on.)*
11. **One session writer.** `wp_set_auth_cookie` has exactly one call site in
    `includes/`, and it fires `wp_login`. *(Finding 13 — WooCommerce's cart
    merge depends on this and nothing asserted it.)*

Rules 5, 6, 7, 9 and 10 are written before the code they describe exists, so each one
must assert its subject was **found** before counting anything — a rule that
narrows to nothing and passes vacuously is the failure mode 10.0's PENDING rows
were written to avoid.
