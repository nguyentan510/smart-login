# 19.4 — The trigger contract

Spec: [`../sign-in-anywhere.md`](../sign-in-anywhere.md), decision 4.
Status: [`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Turn rule 8 green. `abc.com/abc-xyz?smart_login_step=identify` opens
the dialog, `#login` is the short way to write it, and both still go somewhere
useful when the script does not run.

**This brief was rewritten after finding 11.** Its first draft made `#login` the
mechanism. `?smart_login_step=` already existed, already allowlisted, already
generated by `Flow::url()` — the first draft was adding a third vocabulary for a
concept that had two.

## Files

- `assets/js/smart-login-launcher.js`
- `includes/Frontend/class-login-dialog.php` — the localized contract, `noindex`
- `includes/Frontend/class-shortcodes.php` — `[smart_login_button]`
- `README.md` — the contract, because it is a public API

## Steps

1. **The query parameter is canonical.** `Flow::step()` already reads it and
   already allowlists it against `PUBLIC_STEPS` (`class-flow.php:78-80`); the
   only new work is that a page rendering the dialog shell opens it on load. No
   new parameter name, no second reader.
2. **The hash is an alias, resolved to the canonical form.** `#login` and
   `#dang-nhap` → `identify`; `#register` and `#dang-ky` → `identify` with
   `mode=register`; `#forgot` → `forgot`. A map, not a chain of special cases.
   An unknown fragment is left entirely alone — the theme may own it.
3. `data-smart-login="<step>"` for elements that are not links, and
   `window.SmartLogin.open( step )` / `.close()` for other code.
4. The allowlist is localized from `Flow::PUBLIC_STEPS` rather than restated in
   JS. `password`, `signup` and `onboard` stay out, for the reason the comment
   above that constant already gives.
5. **Degradation.** The canonical form needs none — a page with
   `?smart_login_step=identify` and no working script still renders whatever
   that page renders. For the hash, every `a[href="#login"]` has its click
   intercepted, and only its click: the `href` is untouched, so a blocked script
   leaves an ordinary in-page anchor rather than a rewritten link the plugin is
   now responsible for.
6. `[smart_login_button]` plus a block wrapper, so a site built in an editor can
   place a trigger without touching a template.
7. Opening pushes no history entry; closing strips the parameter or the fragment
   with `replaceState`, so the back button does not walk the visitor through a
   sequence of dialogs.
8. **`noindex` on the dialog-open variant**, and the page's canonical URL left
   untouched. A query parameter creates a second URL for the same content, and
   this is the sub-phase that owns that cost.
9. **Signed in:** the trigger is stripped and nothing opens. `[smart_account]`
   owns the account surface and this does not become a second door to it.

## Acceptance

- Rule 8 green
- Every alias resolves to a step in `Flow::PUBLIC_STEPS`; a fragment outside the
  map leaves the DOM untouched, asserted directly
- `?smart_login_step=identify` with the script blocked still renders the flow on
  a page that hosts the shortcode — the property the hash cannot have
- No `a[href]` differs before and after the launcher runs, asserted over the DOM
- The dialog-open variant carries `noindex`; the canonical link tag is unchanged
- Back button after open-then-close returns to the previous **page**
- Every other suite at its previous count

## Not in scope

Capturing the site's existing login links — that is 19.8, and it is a click
interception with its own bounds rather than a spelling of this contract.

Landed in the same commit as 19.3 — see that brief's outcome for why the
launcher could not be split in half.

### The allowlist is localized, never restated

`Flow::public_steps()` returns a copy of the constant, which stays private: it
is the authority, and a caller that could edit it would be a second one. The
alias map is filtered through the same list, so an alias cannot resolve to
something the server would refuse — an alias pointing outside the allowlist
would be a second allowlist wearing a shorter name.

### Degradation needed no work for the canonical form

`?smart_login_step=identify` renders the flow on a page that hosts the shortcode
whether or not any script runs — the property a fragment cannot have, and the
reason the query parameter is canonical rather than merely supported.

For the hash, the launcher intercepts the click and **nothing else**: no `href`
is read back, rewritten, or replaced. `[smart_login_button]` renders an anchor
whose `href` is the real sign-in page for the same reason.

### The query parameter's cost is paid here

A second URL for the same content. `wp_robots` marks the dialog-open variant
`noindex` and the page's canonical tag is left alone, so the two are already
declared to be one page. Closing strips the parameter with `replaceState` —
opening pushed no history entry, so closing must not add one, or a refresh
reopens the dialog and the back button walks through a sequence of them.
