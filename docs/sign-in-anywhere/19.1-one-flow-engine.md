# 19.1 — One flow engine

Spec: [`../sign-in-anywhere.md`](../sign-in-anywhere.md), decision 2.
Status: [`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Turn rules 1 and 2 green. The identifier-first state machine currently
exists once, in `FormController`, on the HTML path only. Extract it so the popup
can drive the same code rather than a copy of it.

This is the sub-phase the phase stands on. Everything visible is downstream of
it, and building the dialog first would mean building it against an endpoint
that does not exist.

## Files

- `includes/Auth/class-flow-engine.php` — new
- `includes/Frontend/class-form-controller.php` — handlers delegate
- `includes/Frontend/class-rest-controller.php` — `identify` route added

## Steps

1. `FlowEngine` takes a step name and an input array and returns a **decision**:
   the next step, its data, and any notices. It performs no output, sets no
   cookies it does not already own, and issues no redirect. It is the thing both
   controllers ask.
2. The six handlers `FormController` owns — `identify`, `signup`, `verify_otp`,
   `resend_otp`, `login`, `forgot`, `reset_password` — move their decision bodies
   into it. `FormController::dispatch()` (`:63-124`) keeps the routing, the
   `RequestGuard` verification and the redirect; those are HTTP concerns and
   belong to a controller.
3. `POST smart-login/v1/identify` is registered, calling the same engine. This
   is the route finding 3 says is missing; it is added here rather than in the
   fragment sub-phase so the parity rule can go green against JSON before any
   HTML is involved.
4. **The guards stay where they are.** `RateLimiter::check_identify()` runs
   before the lookup for the reason `handle_identify()` already documents at
   `:113-116` — the lookup is the enumeration oracle, so a limit applied
   afterwards leaves the oracle intact. The engine must not reorder this.
5. `Captcha::check()` likewise keeps its position.

## Acceptance

- Rules 1 and 2 green
- **Every other suite at its previous count.** This is a refactor: an extraction
  that changes behaviour has failed even if the new suite is green
- `tests/security/` unchanged, in particular the identify rate-limit ordering
- One commit; the diff reads as "moved", not "rewrote"

## Not in scope

The fragment renderer, the dialog, the redirect policy. `identify` returns JSON
here; HTML comes in 19.2.
