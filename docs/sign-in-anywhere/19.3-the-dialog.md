# 19.3 — The dialog

Spec: [`../sign-in-anywhere.md`](../sign-in-anywhere.md), decisions 5 and 7.
Status: [`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Turn rules 4, 5 and 6 green. The shell the fragment lands in, and the
two-stage asset load that keeps it off the critical path of every page.

## Files

- `includes/Frontend/class-login-dialog.php` — new; the shell and the enqueue
- `assets/js/smart-login-launcher.js` — new; small, site-wide
- `assets/js/smart-login-dialog.js` — new; loaded on first open
- `assets/css/smart-login-dialog.css` — new
- `templates/form-auth.php` — id scoping
- `includes/Frontend/class-assets.php` — the `is_singular()` limit

## Steps

1. The shell is a native `<dialog>` emitted on `wp_footer` at a late priority,
   containing a heading, a close button and an empty region. **No form, no
   nonce, no `RequestGuard::fields()`** — that is rule 4, and it is what makes
   the shell safe for a full-page cache to serve.
2. `showModal()` supplies the focus trap, `Esc`, the inert background and the
   top layer. The three things it does not supply are written by hand: scroll
   lock on `<body>`, focus returned to the element that opened it, and a refusal
   to close while a request is in flight.
3. **Ids are scoped.** `templates/form-auth.php:94-104` hard-codes
   `id="sl-identity"` and `autofocus`. Every id in the identify template takes a
   render-scoped prefix, and `autofocus` is applied by the dialog on open rather
   than by the markup — a page holding the shortcode *and* the shell must not
   have two controls claiming focus.
4. Two-stage load: the launcher is enqueued site-wide with no shortcode
   condition, localized with the URLs of the main stylesheet, the main script,
   the dialog pair and — when registered — the captcha script. First open
   injects them, subsequent opens do not.
5. `Assets::maybe_enqueue()` drops its `is_singular()` gate for the launcher
   only (`class-assets.php:32-49`). The main bundle keeps every condition it has
   today; nothing that loads on a page now stops loading.
6. **Submit stays disabled until the fragment's stamp is `MIN_FILL_SECONDS`
   old.** Finding 6: two seconds is unreachable for a human typing a phone
   number and entirely reachable for a password manager filling a password
   field. The visitor sees a button that enables itself, not an error that
   accuses them of being a bot. The server-side guard is untouched.

## Acceptance

- Rules 4, 5 and 6 green
- The shell rendered into a page that also carries `[smart_login]`: zero
  duplicate ids, at most one `autofocus` — measured with
  `tests/visual/render.php`, the tool 18.1 committed for exactly this
- A page with no interaction loads the launcher and **nothing else** from this
  plugin: asserted on the enqueued handle list, not by reading the code
- Opening twice injects the bundle once
- Every other suite at its previous count

## Not in scope

The trigger contract — this sub-phase's dialog opens only from
`window.SmartLogin.open()`. `#login` is 19.4.
