# 20.5 — One word, one meaning

Spec: [`../sending-a-code.md`](../sending-a-code.md) D4.
Status: [`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Rule 16 goes green, which means no word on a settings screen names two
different things.

The guard rail was written in 20.0 and has been red since. This sub-phase is the
one that has no structural work in it at all — every change is a string.

## The renames

**"Nhà cung cấp" named three settings on three tabs.** Each gets the noun it
actually is:

| Where | Becomes |
| --- | --- |
| section `provider` | Nhà cung cấp **đăng nhập** |
| `sms.preset` | Nhà cung cấp **SMS** |
| `security.captcha_provider` | **Dịch vụ chống robot** |
| `AccountProvisioner`'s refusal | names the login provider |

The captcha field is here because Rule 16 found it and the spec had not — it was
added to this sub-phase's scope in 20.0's outcome. It is not called "Nhà cung cấp
captcha": that would pass the rule on a technicality while leaving the reader with
the same word for a third thing.

**"Webhook" belongs to the event tab and appears six times outside it.** All six
are on the SMS side, which is exactly the collision that produced the report — an
administrator holding an n8n URL saw the word on both screens.

| Where | Becomes |
| --- | --- |
| section `automation` label | Endpoint nhận sự kiện |
| `sms.enabled` help | Bật kênh gửi mã tới số điện thoại |
| `generic` preset | Gửi JSON tới endpoint của bạn (n8n / Make / Zapier) |
| its `endpoint` credential | URL nhận yêu cầu |
| `WebhookTester`'s refusal | names the SMS channel |
| `WebhookTransport`'s refusal | names the SMS channel |

The platform names stay in the `generic` label. They are the thing an
administrator recognises, and dropping them to avoid a word would trade one
confusion for another.

**Two stale sentences about routing**, which describe a table 20.1 deleted:
`woo.sms_cost`'s help and the admin-alert help in `MailRegistry`.

## What is not renamed

`WebhookTransport`, `class-webhook-tester.php`, `sms.*`. D4 reserves the word in
**labels**; the class names are internal and never reach a screen, and renaming
them would cross every boundary no test covers for no reader's benefit. This
project has been bitten by a rename five times and none of those was a label.

### What the plan got right, for once

Nothing in this sub-phase surprised it. That is worth recording rather than
passing over: 20.0 measured the vocabulary against the registry instead of
counting by eye, so the list of renames was already exact before any of them was
made — including `security.captcha_provider`, which the spec had missed entirely
and which the rule found in its first run.

A sub-phase whose brief needed no correction is the one whose guard rail was
written first and asked the code rather than the documentation.

### What was found along the way

**One rename was a technicality worth refusing.** `security.captcha_provider`
could have become "Nhà cung cấp captcha", which passes Rule 16 — the check for
that phrase is exact-match, so any suffix satisfies it. It is now **Dịch vụ chống
robot**, matching its own section heading. A rule you can satisfy without fixing
the thing it describes is a rule you have started lying to.

**Six of the seven "Webhook" strings were on the SMS side**, which is the
collision that produced the report in a single number. The word now appears
nowhere in a label; it survives only in class names, which never reach a screen.

**Two sentences still described the routing table** — `woo.sms_cost`'s help and
the admin-alert help in `MailRegistry` — three sub-phases after 20.1 deleted it.
Neither is a label Rule 16 inspects, and no test could have found them. They were
found by reading every string the grep returned rather than only the ones the
rule flagged, which is the only method available for this class of staleness.

### Not done, deliberately

`WebhookTransport`, `class-webhook-tester.php` and the `sms.*` paths keep their
names. D4 reserves the word in **labels**; these are internal, and renaming them
would cross every boundary no test covers to change nothing a reader sees.
