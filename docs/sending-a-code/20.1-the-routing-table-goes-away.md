# 20.1 — The routing table goes away

Spec: [`../sending-a-code.md`](../sending-a-code.md) D1.
Status: [`../refactor-plan.md`](../refactor-plan.md).

**Goal.** The identity channel decides the transport. There is no setting in
between, so there is no cell an administrator can land in where nothing is
delivered and nothing says so.

Runs last of the three structural sub-phases: 20.2 built the destination, 20.3
moved the data, and this removes the shell. Rules 14 and 15 are allowed to go
green here and nowhere earlier.

## What goes, and what each consumer becomes

| Today | After |
| --- | --- |
| `TransportRouter::ROUTES` | `CHANNEL_TRANSPORT` — `phone => sms`, `email => email`, no settings path |
| `delivery.route_phone`, `delivery.route_email` | deleted from the registry |
| `AutomationTransport` | **deleted**. Its transport role is the signed provider now |
| `Readiness` reading `ROUTES` and `route_email` | asks the router which transport serves a channel, which is now a constant |
| `SettingsScreen::automation_role()` | the endpoint has one role left, so the three-way message collapses to two |
| `WebhookTester::test_automation()` | posts a **bus ping**, not an OTP envelope |

The class is deleted rather than left unregistered because Rule 15's companion
requires every `implements TransportInterface` file in the tree to be on the
declared OTP path — so a retired transport that still declares itself one keeps
`AutomationEndpoint` on that path, and Rule 15 stays red for ever.

   `AutomationTransport` out of the default map.
2. Delete the class. Grep `includes/ templates/ tests/ docs/` for the name before

### What the plan got wrong

**The brief listed six consumers and there were nine.** Three only appeared once
the constant was gone, and all three were rules rather than code:

- **10.1's own two assertions** — *"a phone destination follows the routing
  table"* — asserted the behaviour D1 reverses. They and Rule 14 cannot both be
  kept; the newer one describes the property an administrator actually walked
  into. Retired in place, with the reason written where they were.
- **Rule 5, "the routing table cannot dangle"**, which was carefully built to
  report PENDING rather than pass when the fields were absent — *"a rule that
  passes for want of a subject reports the opposite of the truth"*. Correct in
  10.1 and misleading now, because 20.1 removes the subject deliberately. Retired
  with a `ow_note` pointing at Rule 14, which holds the strictly stronger
  property: not "every choice resolves" but "no setting names a transport", which
  makes a dangling choice unrepresentable rather than checked.
- **10.5's readiness scenario**, built on a channel routed away from its built-in
  transport. Repointed rather than retired, because the property underneath is
  still live — a channel whose transport cannot send must be reported blocking,
  by name. The modern spelling of the same broken site is the signed provider
  selected with no endpoint, and it reproduces exactly.

Retiring a rule needs a written reason, so none of the three was deleted quietly.
A rule that vanishes with no note is indistinguishable from one somebody removed
to get a green run.

### What was found along the way

**A missing `*/` cost twenty minutes and is worth recording.** Replacing the 10.1
assertions with a comment left the block unterminated, which silently swallowed
the next fifty lines — including Rule 3's setup — and surfaced as
`array_keys(): Argument #1 must be of type array, null given` a hundred lines
further down. The lint suite could not see it because the file still parsed. The
lesson is not "close your comments"; it is that a suite whose *setup* can be
commented out will report the absence of a rule as a passing run.

**Deleting the class was not optional.** Rule 15's companion requires every
`implements TransportInterface` file to be on the declared OTP path, so a retired
transport that still declared itself one would have kept `AutomationEndpoint` on
that path and held Rule 15 red for ever. The companion earned its keep on its
first real use.

**The test button had to change meaning, not disappear.** `test_automation()` sent
an OTP envelope because the endpoint could be a transport. It now sends a signed
`test.ping` carrying no code, blocking so the operator sees an answer — and takes
no destination and no code, which is the visible shape of the change. Removing a
transport must not remove an operator's only way to check an endpoint is up.

### Not done, deliberately

`automation.*` all still exist and the bus still uses them. The tab keeps its name
and place until 20.4.
