# 15.2 — Delete the migrations

Spec: [`../unreleased-install.md`](../unreleased-install.md). Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Remove every path that exists to upgrade an install, and reset the version.

## Files

- `includes/class-installer.php`
- `smart-login.php` — `SMART_LOGIN_DB_VERSION` → `1`
- `uninstall.php` — the `external_identities` drop, and the missing cursor option
- `tests/integration/run-wordpress-gate.php`, `tests/integration/run-abuse-gate.php`

## Steps

1. Delete `migrate_settings_shape()`, `legacy_key_map()`, `recreate_renamed_tables()`,
   `drop_legacy_tables()` and `backfill_provider_emails()` with its cursor constants.

2. `maybe_upgrade()` **stays**, reduced to: version differs → `install_tables()` →
   write the version. The mechanism is how the next schema change arrives; only its
   contents were about the past.

3. `SMART_LOGIN_DB_VERSION` → `1`. There is nothing to upgrade from, and a version
   that starts at 6 tells a story about installs that do not exist.

4. `uninstall.php` loses the `external_identities` drop and gains whatever 15.0's step
   5 says is missing.

5. The 14.5 assertions in the WordPress gate go with the code they assert. **Not
   silently**: their Outcome recorded a real defect, and the tracker row is what keeps
   that finding after the code is gone.

## Acceptance

15.0's deletion rules for these five surfaces go green. The install gate passes end to
end, including step 5. `pending_schema_changes()` stays empty on a fresh activate at
version 1. Every other suite unchanged.

## Not in scope

`install_tables()` and `schema()`. Nothing about creating tables is legacy.
