# 18.1 — The renderer

Spec: [`../rendered-surface.md`](../rendered-surface.md), decisions 1 and 2.
Status: [`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Turn rules 1, 4 and 5 green. Phase 17 built this in a scratch
directory, used it to find two defects no suite could, and deleted it with the
session. This is the same tool, committed.

## Files

- `tests/visual/render.php` — new
- `tests/visual/README.md` — new: the measurement protocol
- `composer.json` — one script alias

## Steps

1. `php tests/visual/render.php <surface>` builds one page from the real
   templates, the real stubs and the real stylesheet, into `build/visual/`
   (already git-ignored) and prints the path.
2. **The stylesheet is inlined, not linked.** A rendered file has to open from
   anywhere — a temp directory, an attachment, a bug report — without the CSS
   resolving beside it.
3. `--all` builds every surface, plus an `account` composite that renders the
   four cards and the status notice as one page, which is the thing anybody
   actually wants to look at.
4. Fixtures come from the shapes `run-template-tests.php` already declares, so a
   fixture cannot drift between the smoke test and the picture.
5. `tests/visual/README.md` writes down the measurements a browser is needed
   for, as commands and expected readings rather than as prose: viewport
   overflow at 375 and 480, control heights in `.sl-contact-row`, target sizes
   in `.sl-row`, and the keyboard order through one card.

## Acceptance

- Rules 1, 4 and 5 green
- `php tests/visual/render.php account` produces a file that opens standalone —
  checked by opening it, which is the entire point of the sub-phase
- Every other suite at its previous count
- Nothing added to `.github/workflows/php-quality.yml`, and no `package.json`

## Not in scope

Automating the browser. The spec argues that deferral; the README is what
replaces it, and it is honest about being a protocol rather than a gate.

### The fixtures got one owner, and the extraction broke a rule

`tests/template-fixtures.php`, lifted unchanged out of `run-template-tests.php`,
with two readers. A picture built from a second set of arguments would be a
picture of a screen no suite has ever executed, which is the one thing a visual
tool must not be.

Moving them turned the sign-in card suite red:

```text
Sign-in card: 10 passed, 2 failed
  FAIL  the partials/account/contact fixture carries a non-federated identity
  FAIL  the partials/linked-identities fixture carries a non-federated identity
```

16.0's rule 5 reads the fixture *source* to check the smoke test still exercises
the branch Phase 16 exists to fix, and it was reading a file the fixtures had
left. Green again once repointed.

This is the sixth time in this project that a rename crossed a boundary no test
covers — and the first time a guard rail caught it in the same run rather than a
phase later. CLAUDE.md lists the other five.

### The protocol had to be honest about the tool

Two of the five readings needed a caveat written into the README rather than
discovered by whoever takes them next:

- The contact editor renders closed, so the height comparison reads `0 × 0`
  unless the `hidden` attribute comes off by hand. A reading of zero that looks
  like a pass is the exact shape of mistake this file exists to prevent.
- The rendered page carries no plugin JavaScript at all, which puts it
  permanently in the state reading 5 is about. That one comes free; every other
  one has to be taken.

### Not done

No `package.json`, nothing added to the CI workflow. One composer alias,
`composer visual`.
