# 21.2 — One glyph vocabulary

Spec: [`../account-menu.md`](../account-menu.md), decision 6.
Status: [`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Turn rules 2 and 3 green. One place decides what a UI glyph looks like,
and an icon that is not in it cannot be stored, let alone rendered.

## Files

- `includes/Frontend/class-icon-set.php` — new
- `includes/Frontend/class-account-form.php` — `sections_meta()` reads from it
- `templates/onboarding.php` — **found by 21.0's rule 2**, draws its own glyph
- `templates/partials/password-field.php` — likewise
- `templates/partials/account/card-head.php` — unchanged, and that is the test

## Steps

1. `IconSet::get( string $name ): string` returns inline SVG at 18×18, stroked,
   `currentColor` — the geometry `sections_meta()` already established
   (`class-account-form.php:93-96`), lifted rather than re-decided.
2. `IconSet::names(): array` returns name => Vietnamese label, and it is what the
   settings `<select>` is built from. One list, so a name the picker offers is a
   name the renderer has by construction.
3. Ten names to start: `user`, `lock`, `map-pin`, `shield`, `box`, `file-text`,
   `calendar`, `pill`, `heart`, `log-out`. The first four are the four already
   inlined in `sections_meta()` and their paths are moved verbatim — this
   sub-phase does not redraw an icon.
4. `IconSet::FALLBACK` is `user`. `get()` with an unknown name returns the
   fallback's markup, and never the input.
5. `sections_meta()` keeps its four entries, their labels and their order
   (spec deferral). Only the `$svg` closure goes, replaced by an `IconSet` call.
6. **Two call sites the spec did not count.** 21.0's rule 2 found inline SVG in
   `templates/onboarding.php` and `templates/partials/password-field.php` as
   well. Both are UI glyphs, neither is a brand mark, so neither qualifies for
   the exemption and both convert here. Whatever names they need are added to
   the set in step 3 rather than drawn inline "just this once".
6. **Provider marks are not touched.** `ProviderMark::icon_svg()` returns a
   trademark in its owner's colours (`class-provider-mark.php:63`); it is named
   in rule 2 as the exemption rather than left to be matched by a pattern.

## Acceptance

- Rules 2 and 3 green
- `card-head.php` is **byte-identical** before and after, and the account-card
  suite's rendered output is unchanged — the refactor is invisible or it is
  wrong
- `IconSet::get( 'no-such-icon' )` returns the fallback markup; the string
  `no-such-icon` appears nowhere in the output
- Every name in `IconSet::names()` resolves to non-empty markup, asserted by
  iterating the list rather than by spot-checking
- Every other suite at its previous count

## Not in scope

Redrawing any of the four existing icons, or letting a site add an icon. A filter
over the set is a later question and it has a real answer to find first — an
added icon is user-supplied SVG, and rule 3 exists to keep that off the page.
