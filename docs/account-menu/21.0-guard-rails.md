**Goal.** Land a suite that fails, and whose failures are the specification the
rest of the phase is built against. A rule written after the fix cannot fail, and
a rule that has never failed is a comment.

## Rules

Each names the finding or decision it comes from. A rule whose subject does not
exist yet reports **PENDING**, not PASS — the 10.0 precedent: a rule that passes
for want of a subject states the opposite of the truth.

1. **Tokens have one home.** No design token is declared outside the token
   stylesheet, and `.omniwp` declares no custom property of its own.
   Structural, over `assets/css/`. *(Decision 13.)*
2. **One glyph vocabulary.** No `<svg` literal appears in `includes/` or
   `templates/` outside `IconSet` and the provider mark. Structural, with
   `ProviderMark` named as the exemption rather than matched by accident.
   *(Finding 8, decision 6.)*
3. **An unknown icon is unrepresentable.** Sanitising a name outside `IconSet`
   yields the fallback name, never the input; and no value that came from
   settings reaches the DOM as markup. *(Decision 6.)*
4. **Destinations are not sections.** `AccountMenu` never calls
   `sections_meta()`, and every key in `sections_meta()` is a key of
   `AccountForm::SECTIONS`. The second half is the existing invariant, asserted
   for the first time. *(Finding 4.)*
5. **Stable keys.** Every entry key matches `[a-z0-9_-]+`, the pinned keys are
   `account` and `logout`, and no entry key collides with a section key.
   *(Decision 4.)*
6. **The entry shape is four keys.** Every entry has exactly `key`, `label`,
   `icon`, `url` and nothing else. This rule exists to fail the day somebody adds
   a fifth without a spec change. *(Decision 5.)*
7. **The menu is never empty.** With the option cleared, `AccountMenu::items()`
   returns at least two entries, each with a non-empty `label` and a non-empty
   `url`. *(Decision 3.)*
8. **Logout is plugin-owned.** No settings input produces the logout entry; its
   URL is the one `wp_logout_url()` returns, and it is last in the list.
   *(Finding 7.)*
9. **One source for every surface.** Nothing under `templates/` reads the menu
   option; `AccountMenu` is the only reader. Structural. *(Decision 2.)*
10. **Two states, never both.** Signed out the shortcode renders a trigger and no
    menu; signed in it renders a menu and no `data-omniwp` trigger.
    Behavioural, over rendered markup in both states. *(Finding 3, decision 1.)*
11. **The header button does not inherit the form button.** The rendered button
    carries no `sl-btn` class. *(Finding 2, decision 7.)*
12. **Degradation.** With no script on the page, the signed-out button is an
    anchor whose `href` is a real URL, and the signed-in menu is a `<details>`
    element that opens without JavaScript. Asserted over the DOM.
    *(Decision 8.)*

### The suite lied about itself on the day it landed

The most valuable thing this sub-phase produced was a failure in its own first
draft. `shortcode_atts()` was not stubbed — no suite had ever rendered a
shortcode directly — so `render_button()` threw, the helper caught the throw and
returned `''`, and **three rules passed against an empty string**. Rules 10, 11
and 12 are all phrased as absences, and an absence is satisfied by nothing at
all.

A guard-rail suite reporting a false green on its first run is the exact defect
the whole phase is organised against, and it was invisible in the summary: `2
passed, 11 failed` looked like a healthy red.

Two changes, because one would not have been enough:

- `shortcode_atts()` added to `tests/template-stubs.php`, with the reason
  written above it
- the render helper returns `array{ok, markup, error}` instead of a string, and
  every absence rule reports **PENDING** unless the markup actually rendered

The second is the durable one. The stub fixes today's instance; the structure
means the next unstubbed function cannot be mistaken for a passing rule.

### Rule 12 was measuring the fixture, not the button

`Flow::login_url()` returns `''` with no host page, so the button fell back to
`#login` and the degradation rule failed for a reason that had nothing to do
with degradation. The suite now installs a `OMNIWP_login_url` filter, and
the rule asserts a real `https://` href — the property decision 8 actually
claims.

### Inline SVG is in four files, not two

The spec's finding 8 named `sections_meta()` and `ProviderMark`. Rule 2 found two
more glyph producers nobody had counted: `templates/onboarding.php` and
`templates/partials/password-field.php`, each drawing its own icon inline.

**This widens 21.2.** Both are UI glyphs and both belong in `IconSet`; neither is
a brand mark, so neither qualifies for the exemption. The sub-phase's step 3 said
"ten names to start" and the four moved from `sections_meta()` — it now has two
more call sites to convert.

### Rule 4's second half passes today, legitimately

`every sections_meta() key is a declared section` is green on arrival. It is an
invariant that already held and had never been asserted; it is not passing for
want of a subject, and it is the half of rule 4 that will keep holding while the
other half waits for `AccountMenu`.

### What the plan got right

The ordering. Rule 1 fails on a token file that does not exist, and every later
sub-phase would have needed a colour from somewhere — writing 21.1 first was not
a preference, and the red output says so on the first line.
