# 17.0 — Guard rails

Spec: [`../account-card.md`](../account-card.md). Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Land eight rules red, before any production file moves. One rule per
sub-phase that follows, so "17.4 is done" and "rule 5 is green" are the same
sentence.

Its own suite, for the reason 16.0 gives: the account surface suite has been
`required` since 8.3, and rules that are meant to fail cannot live in a suite
that blocks.

## Files

- `tests/identity/run-account-card-tests.php` — new, registered `spec`
- `tests/run-all.php` — one row
- Nothing under `includes/`, `templates/` or `assets/`

## The rules

**1. The provider's own mark, wherever the provider is named (17.1).** Render
`partials/linked-identities` with a google identity, and
`partials/account/providers` with a link invitation. Both must contain `<svg`.
Red today at zero: `icon_svg()` has been on the interface since Phase 12 and only
the sign-in screen calls it.

**2. The account surface reads the scale (17.2).** Inside the account-surface
region of `smart-login.css`, no `margin`, `padding`, `gap`, `row-gap`,
`column-gap` or `font-size` may carry a literal `px`. The token block must
declare `--sl-space-1..6` and `--sl-fs-xs..xl`.

The region is located by its section comment. The rule asserts the marker exists
first, so renaming the comment fails loudly instead of silently narrowing the
rule to nothing — the 16.0 failure, one level up.

**3. Width intent is carried by the element (17.3).** No selector may set
`width: auto` on `.sl-btn` from an ancestor. Red today at three
(`.sl-savebar .sl-btn`, `.sl-identity-unlink .sl-btn`, `.sl-contact-row .sl-btn`).

And: every row-level action in the account partials carries `sl-action`. Red
today at three, in three different elements.

**4. The address the card names is the address it writes (17.4).** Behavioural.
Call `AddressFields::save_for_user()` against the stub meta store and assert
`shipping_state`, `shipping_city`, `shipping_country`, `shipping_address_1` and
`smartlogin_shipping_ward_code` are all written. Red today at zero — nothing in
the tree writes a shipping field for a user profile.

The second half is a copy rule: no template may claim "cả hai" while the writer
writes one.

**5. A password write records when it happened (17.6).** A companion rule: any
file under `includes/` that writes `user_pass` or calls `wp_set_password()` must
also call `SecurityMeta::record_password_change()`. Red today at three.

Plus the pure half: `describe_password_age()` returns `''` for an account with no
stored timestamp, and buckets a known one.

**6. The notice states the reason it already has (17.5).** Render
`partials/account/status` with a missing `address`, and assert the rendered text
contains the reason string from `onboarding_reasons()` — and that the template
does not contain that string as a literal. Red today: the partial renders
`implode()` of labels.

**7. The fraction has a denominator, and one owner (17.7).** `status()` must
return integer `total` and `done`, and no template may count the missing arrays
itself. Red today at absent.

**8. Each card names itself with its own mark (17.8).** Render all four sections
and collect the icon markup. There must be four, and they must be **distinct**.
Red today: four identical `&#9679;`.

Plus the ownership half: the literal `sl-card__icon` span appears in exactly one
template.

### There are four password writers, not three

The brief said three. The companion rule found a fourth, and the fourth is the
one that must **not** record: `AccountProvisioner` writes a 64-character random
string for an account signing in through a provider, whose holder has never seen
it.

So `sl_require_companion()` grew an allowlist parameter, matching the one
`sl_forbid_pattern()` has carried since Phase 4 and for the same reason. This is
the return on landing rules before features: a recorder written first and
instrumented afterwards would have hit all four writers and put a wrong sentence
on every provider account's card.

### One rule was narrowed in 17.3, and it is recorded there

Rule 3's second half was written as "no `sl-btn--outline` in any of the three
partials" and flagged two controls that are not row actions at all. Narrowed in
the sub-phase that turned it green, before the markup was contorted to satisfy a
rule that was measuring the wrong thing. See
[`17.3-one-action-shape.md`](17.3-one-action-shape.md).

### A ninth rule was added mid-phase, after the browser found what no suite could

`.screen-reader-text` is declared by themes, not by WordPress's front end, and
this plugin has used it in three templates since 8.4 without declaring it.
Written after the defect rather than before — the exception to this brief's own
premise, declared rather than hidden, with its red output in 17.3's commit.
