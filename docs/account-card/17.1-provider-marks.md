# 17.1 — The provider's own mark

Spec: [`../account-card.md`](../account-card.md), decision 8. Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Turn rule 1 green. The cheapest sub-phase in the phase and the only one
that adds no new asset: `icon_svg()` has existed since Phase 12 and the account
card has never called it.

## Files

- `includes/Frontend/class-provider-mark.php` — new
- `templates/partials/linked-identities.php`
- `templates/partials/account/providers.php`
- `assets/css/smart-login.css` — one rule for the mark in a row

## Steps

1. `ProviderMark::svg( string $channel ): string` — resolve through
   `ProviderRegistry::get()`, return `''` for a channel no provider claims.
   `get()` and not `available()`: an account can hold a Google identity on a site
   where Google has since been switched off, and that row still has to draw.
2. The linked row renders the mark before the label.
3. The invitation button renders the mark before its text, the way
   `form-auth.php:130-140` already does on the sign-in screen.
4. One CSS rule sizing the mark inside a row. No new colour: the SVGs carry the
   brand's own.

## Acceptance

- Rule 1 green
- A channel with no registered provider renders no mark and no error — asserted,
  because `linked()` returns `email` and `phone` rows too and the helper will be
  handed them
- Every other suite at its previous count

## Not in scope

The card heading icons (17.8) and the row restructure (17.3). This sub-phase adds
a mark to the markup that exists.
