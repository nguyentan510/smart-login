# 17.3 — One shape for one class of action

Spec: [`../account-card.md`](../account-card.md), decisions 2 and 3. Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Turn rule 3 green. Three row-level actions, three elements, three
visual weights — one `.sl-action`.

## Files

- `assets/css/omniwp.css`
- `templates/partials/account/contact.php`
- `templates/partials/account/providers.php`
- `templates/partials/linked-identities.php`

## Steps

1. `.sl-action` — small, quiet, sized to a row; `.sl-action--danger` for the
   destructive one. Built on the tokens 17.2 declared.
2. "Đổi" / "Thêm" and the "Bỏ liên kết" summary both carry it. `<details>` stays
   as the mechanism — it holds a password form and works with JavaScript off —
   and only its summary changes appearance.
3. The provider invitation becomes a row: `Zalo · chưa liên kết · Liên kết`.
   16.3 folded the linked providers into the contact list; this is the last piece
   of the geometry that preceded it. `data-sl-provider-mode="link"` and the start
   URL are unchanged, so the single-template rule in the account surface suite
   still holds.
4. `.sl-btn--inline` replaces the three ancestor-keyed `width: auto` overrides.
   The base keeps `width: 100%` — the spec counts 20 of 27 call sites wanting it
   and argues the decision.

## Acceptance

- Rule 3 green, both halves
- The unlink form still submits with JavaScript disabled — the `<details>` is
  the mechanism and it must not become a button that needs a listener
- Keyboard-only pass over the three actions
- Every other suite at its previous count

## Not in scope

The save bar. It is a page-level control, not a row-level one, and
`.sl-savebar .sl-btn` becomes `.sl-btn--inline` on the element without changing
what the bar is.

### A rule that was measuring the wrong thing, narrowed before the code was bent

17.0 wrote the second half as "no `sl-btn--outline` in any of the three
partials". That flagged two controls that are not row actions at all:
`contact.php`'s "Gửi mã", the primary action of the editor it sits in, and
`linked-identities.php`'s "Xác nhận bỏ liên kết", the submit of a confirmation
form. Both are buttons and should look like buttons.

Narrowed here rather than satisfied by contorting the markup, and it stayed red
on all three halves for the defect it is actually about: no `sl-link--button` in
the three, `sl-action` in all three, and no `sl-btn` at all in `providers.php`.

### A defect the browser found and no suite could

`.screen-reader-text` is a **theme** convention. WordPress declares it in
wp-admin and in the block library; nothing guarantees it on the front end of an
arbitrary theme. Three templates have used it since 8.4 and the plugin has never
declared it — so on a theme without the class, the profile card reads

```text
Họ tên * (bắt buộc)
```

with the parenthetical in the label, and this sub-phase's new "Liên kết" row
would have printed the brand name in every row.

Seen on a rendered page, not in any test. The rule for it was therefore written
**after** the defect rather than before, which the working agreement asks to be
declared rather than hidden — so the commit carries the red it produced first:

```text
FAIL   the plugin does not rely on the theme to hide its own text
       → .screen-reader-text
```

`clip-path`, not `display: none` or `visibility: hidden` — both of those take
the text out of the accessibility tree, which is the opposite of the point.
Scoped under `.omniwp` so a theme that does declare it keeps its own.

### The two acceptance items this brief could not run

The keyboard pass over the three actions, and the `<details>` submitting with
JavaScript off. Both **taken in 18.4**:

- 31 controls in the account composite, DOM order matching reading order, and
  the restyled `<summary class="sl-action">` taking focus at 60 × 32 with a
  visible ring.
- The rendered page carries no JavaScript at all, so the unlink `<details>` and
  the password disclosure were exercised in exactly the state the item is about.
  Both open; the form is a real `POST` carrying `_wpnonce`, `channel` and
  `subject`.

The same pass found something this sub-phase did not consider: with JavaScript
off, "Đổi" is a dead control with no explanation, while the address picker two
cards below has a `<noscript>` doing precisely that job. Recorded as a finding in
[`../rendered-surface/18.4-the-measurements.md`](../rendered-surface/18.4-the-measurements.md)
rather than fixed there.

### The base was not inverted, and that was the right call for a countable reason

20 of the 27 `.sl-btn` in `templates/` want full width. Inverting would have
meant editing 18 call sites across screens Phase 16 has just settled, to shorten
the minority case. What moved is where the exception is written: `.sl-btn--inline`
on the element, instead of three rules keyed on an ancestor.
