# 17.8 — One glyph set, one owner

Spec: [`../account-card.md`](../account-card.md), decision 8. Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Turn rule 8 green. Four cards draw the same red dot. A mark that is
identical in four places distinguishes nothing — it is a slot that was never
filled.

Last, and deliberately so: it is the most visible sub-phase and the least
consequential, which is the trap 10.6, 11.4, 14.6 and 16.3 each named.

## Files

- `includes/Frontend/class-account-form.php` — `sections_meta()`
- `templates/partials/account/card-head.php` — new
- `templates/partials/account/{profile,contact,address,password}.php`
- `assets/css/smart-login.css`

## Steps

1. `headings()` becomes `sections_meta()`: one array, `label` and `icon` per
   section. The four-way drift this project fixed in `FieldRegistry` is the same
   shape — one array decides, so a section cannot have a heading in one place and
   a mark in another.
2. `partials/account/card-head` renders the row. The four partials call it and
   stop carrying the span.
3. Marks are inline SVG at 18×18, matching `icon_svg()`, so the card has one
   glyph size rather than two.
4. `.sl-card__icon` sizes and colours the slot; the previous rule sized a 10px
   text bullet and does not survive.

## Acceptance

- Rule 8 green, both halves — four distinct marks, and the span in one template
- **`headings()` is a rename.** Grep it across `includes/`, `templates/`,
  `tests/` and `docs/` before claiming completion — four callers today, and this
  project has been bitten five times
- The heading is still a real `<h3>` in the document outline; the mark is
  `aria-hidden`
- Every other suite at its previous count

## Not in scope

An icon system for the rest of the plugin. Four marks on four cards, drawn where
the section is already declared.

## Outcome


Suite fully green and **promoted to `required`** here, in the sub-phase that
turned the last two rules, rather than left for later. 15.4 found this suite
kind being abused for four phases; a green suite that cannot block can only hide
the next regression.

### The template suite caught the new partial before anything else did

```text
FAIL  every template has a fixture or a written-down exclusion
Templates: 100 passed, 1 failed
```

That is the mechanism 8.2 built working exactly as designed: a new partial fails
the smoke test the moment it lands and passes once it has a fixture, which makes
"extend the smoke test" automatic rather than remembered. 104 / 0 after.

### The rename was small, which is not the same as safe

Four callers, all templates, plus the two now-unused `AccountForm` imports they
left behind. The grep across `includes/`, `templates/`, `tests/` and `docs/`
turned up one more mention — this phase's own spec, naming the old method as the
thing being renamed, which is correct as written.

### A glyph size, not just a glyph

`.sl-card__icon` sized a 10px text bullet; the marks around it are SVG at 18px.
A card cannot have two glyph systems and look deliberate, so the slot is now a
box the same size as `.sl-provider-icon` — the same measurement, one owner each.
