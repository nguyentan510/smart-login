# 16.0 — Guard rails

Spec: [`../sign-in-card.md`](../sign-in-card.md). Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Land the rules red, before any production file moves. A rule written
after the fix cannot fail, and a rule that has never failed is a comment.

This phase needs its own suite for one reason beyond tidiness: the account
surface suite has been `required` since 8.3, and rules that are red on purpose
cannot live in a suite that blocks.

## Files

- `tests/identity/run-sign-in-card-tests.php` — new, registered `spec`
- `tests/run-all.php` — one row
- Nothing under `includes/`, `templates/` or `assets/`

## The rules

**1. One value, one place.** Render `partials/account/contact` for an account
whose identity list contains its own email address, and count the address. It
must appear exactly once. Behavioural, and red today at two — once whole in the
contact row, once masked in the list below.

Counted by domain, not by the whole address: the masked form keeps the domain
and loses the local part, so a rule matching the full string would pass while
looking straight at the defect.

**2. Đổi for what you own, Bỏ liên kết for what you borrowed.** Rendering
`partials/linked-identities` with a **removable email** identity must produce no
`unlink_identity` control. Rendering it with a removable **google** identity
must produce one. Red on the first half today; the second half is what stops the
first from passing because the template stopped rendering anything at all.

**3. Every input the plugin renders is styled by the plugin.** No `<input>` in
`templates/` of type `text`, `email`, `tel`, `password`, `search` or `number`
without `sl-input` among its classes. Red today with one offender, the unlink
password box.

A class rule, not an instance: this is how the box arrived unstyled in the first
place, and the next partial written in a hurry has the same exposure.

**4. A full-width component declares its own box model.** Every `.sl-*` class
the stylesheet gives `width: 100%` must be covered by the border-box guard that
`:251-267` already establishes for `.sl-input`. A modifier counts as covered
when its base class is (`sl-btn--block` by `sl-btn`), because an element
carrying the modifier carries the base too.

Red today: `.sl-btn` sets `width: 100%` and is not guarded, which is what puts
the confirm button through the side of its panel on a theme that resets
`box-sizing`.

**5. The shared fixture holds the shape the rules are about.** The template
suite's fixtures for `partials/account/contact` and `partials/linked-identities`
must each contain at least one identity with `federated => false`.

A test of a test, and it earns the place. `run-template-tests.php:213` passes
`sl_identities => array()` and `:220` passes one `google` row, so the smoke test
has never executed the branch this phase exists to fix — and once rule 1 is
green, nothing else would notice the fixture quietly losing the case again. This
is 14.4's "green by default unless it names the thing it just made", one level
up.

The two passes are the halves that exist to stop the other halves passing
vacuously — the federated row surviving rule 1's filter, and a federated
identity still offering the control rule 2 takes away from an address.

### The address appears three times, not twice

The brief and the spec both said two. The count is **three**: the contact row
prints it whole, the list prints it masked, and the unlink form carries it a
third time in `<input type="hidden" name="subject">`
(`partials/linked-identities.php:51`).

That third copy is the one worth noticing. The first two are a presentation
defect; the third is the address travelling through a form post as the subject
of a retire operation — which is exactly the control 16.1 removes for
self-asserted channels, so it goes with it rather than being counted down to
two.

### Rule 4 found a second component with the same exposure

`.sl-combo__input` — the address picker's combobox — sets `width: 100%` and is
outside the guard, the same as `.sl-btn`. Nobody had reported it and no
screenshot shows it, which is the argument for a rule that names a property
rather than an instance: the reported defect was one button in one panel.

### A rule that never ran, and looked like it had

The first draft explained the tag-matching regex in a `//` comment containing a
literal PHP close tag. That ends PHP mode. Rules 4 and 5 were echoed to stdout
as HTML and never executed, while the suite still printed a heading for rule 3
and exited — a red suite that was redder than it said.

Caught by reading the output rather than the exit code, and the comment is a
block comment now with the reason written into it. Worth recording because it is
the same shape as the failures this project keeps finding: the gate reported on
what it reached, and nothing reported on what it did not reach.
