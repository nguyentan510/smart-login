# 16.3 — The card's geometry

Spec: [`../sign-in-card.md`](../sign-in-card.md) — decisions 1, 7 and 8. Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** The visible sub-phase, and last for the reason 10.6, 11.4 and 14.6 all
record: every earlier attempt to lay this card out was really an attempt to
decide what belonged in it.

## Files

- `assets/css/smart-login.css`
- `templates/partials/linked-identities.php`
- `templates/partials/account/contact.php`

## Steps

1. **One grid.** Federated rows adopt `.sl-row` and its `108px` label column, so
   every row in the card shares one column. `.sl-identity-item`,
   `.sl-identity-label` and `.sl-identity-value` go with the grid they described.
2. **The border-box guard generalises.** Extend the rule at `:251-267` from
   `.sl-input` to every full-width component, keeping the doubled-class trick and
   the reasoning already written there. Turns 16.0 rule 4 green.
3. **The password box gets its classes** — `sl-label` on the label, `sl-input` on
   the input. Turns 16.0 rule 3 green.
4. **The destructive confirmation stops out-weighing the page.** It is the
   rarest control in the card and currently the largest; it becomes a
   normal-width button that does not exceed the panel it confirms from.
5. **The badge states the effect**, per decision 8. Copy only.

### The hypothesis was right, and it was measured before it was believed

The spec inferred the overflow's cause from a screenshot and said so. Measured
on the live site, in the active theme, on the reported account — the guard's
`box-sizing` declaration disabled and `width: 100%` restored, which is the
pre-16.3 tree reproduced in place:

| | Shipped | Guard removed |
| --- | --- | --- |
| computed `box-sizing` | `border-box` | **`content-box`** |
| button width | 180px | 557px |
| right edge vs the panel's border | −356px, inside | **+21px, outside** |

So a theme rule *is* outranking `.smart-login *`'s `box-sizing: inherit`, and
the button *did* add its padding on the outside. The defect reproduces.

The +21px reconciles with the arithmetic the spec predicted rather than
contradicting it: the panel carries 12px of right padding, so 21px past its
border is ~33px past its content edge — the 32px of horizontal padding plus the
2px of border that a `content-box` button adds. The screenshot estimate of ~34px
was right and the number it should have been compared against was not the one it
looked like.

Worth stating plainly, because it is the argument for the whole rule: **the
component that was reported is not the only one that had this.**
`.sl-combo__input` had it too, silently, and was found by rule 4 rather than by
anybody looking.

### What the card looks like now

One grid. `Số điện thoại`, `Email` and `Google` share a single 108px label
column, and the values line up — which is the thing that made the card read as
two lists stapled together. `Google · Cai Hoa` renders 16.2's display name from
the real linked account, in place of `Google · 1171••••••`. The email row reads
`hoacai.vi@gmail.com · dùng để đăng nhập · Chính · Đổi`, once, in one format.
The confirm button sits inside its panel at 180px, under a password box that is
now a styled full-width field rather than a browser default inline with its
label.

### Two acceptance checks were not run, and are not being claimed

The brief asks for a 480px pass and a keyboard-only pass over the disclosure and
the confirm form. Neither happened: the Chrome extension was not connected for
this session, so the measurement above was run by the repository's owner from a
console rather than by driving the page, and a viewport change and a tab-order
walk are not things that can be handed over as a one-line snippet.

Recorded here rather than quietly dropped, the same way 10.6 recorded that it
never asserted appearance because no wp-admin session existed and one was not
created. The CSS at risk is `@media (max-width: 480px)`, which this sub-phase
did not touch, and the markup changes moved a `<summary>` and an `<input>`
inside the same `<details>` without adding or removing a focusable element.
