# 8.2 — Section contract and renderer

Spec: [`../account-surface.md`](../account-surface.md). Status:
[`../refactor-plan.md`](../refactor-plan.md).

**Goal.** Extract the six sections and the renderer, with **rendered output
unchanged**. That is the safety property of this sub-phase: after it lands the
page must look identical, so any visual difference is a bug rather than a
decision.

## Files

- `templates/partials/account/{identity,contact,providers,profile-extra,address,password}.php` — new
- `includes/Frontend/class-account-form.php` — new renderer
- `templates/woocommerce/form-edit-account.php` — shrinks to an adapter
- `includes/Frontend/class-shortcodes.php` — `render_profile()` starts consuming
  the renderer instead of duplicating its argument assembly (lines 258–271)

## Steps

1. Move markup **verbatim** into the six partials. Resist every improvement —
   they belong to 8.4, and mixing them here destroys the diff property.
2. `providers` becomes a call into the existing
   `partials/linked-identities.php`. Do not copy that markup a third time.
3. Build the renderer. It owns what the template does inline today:
   instantiating `ProfileCompletionService`, `ContactVerificationService` and
   `ProviderRegistry` (lines 29–30, 188), deciding which sections apply from
   `Settings`, and supplying each partial's args.
4. Each section declares `saves_own` — see the contract table in the spec. Wire
   the property now even though nothing reads it until 8.4; adding it later means
   touching all six files again.
5. The Woo template becomes an adapter: context `woocommerce`, Woo's nonce and
   `save_account_details` field, and **all four** `woocommerce_edit_account_form*`
   hook points preserved by name.

## Acceptance

- Rendered HTML for a logged-in fixture is unchanged apart from whitespace **and
  the three declared deltas below**. Capture before and after, diff them — do not
  read the code and conclude
- The 8.0 fitness rule turns green
- `php tests/run-all.php` green; phpcs no worse than its 22-violation baseline
- The Woo page still saves through `WC_Form_Handler`, with a third-party plugin
  hooking `woocommerce_edit_account_form` still rendering its field

### Three declared output changes, and why "unchanged" cannot mean all of it

Amended while doing the work. Two copies collapsing into one owner cannot
preserve both outputs — if it could, there would have been nothing wrong. The
maintained copy wins in each case, and the Woo page is the one that changes:

1. **Profile-status notice.** Gains the `<strong>` heading, the sentence and the
   action link that `profile-summary.php` already renders. Loses the bare
   `implode()` that produces `Địa chỉ, Ngày sinh, Giới tính` on the live page.
2. **Provider invitation.** Starts filtering `unlinked_providers()`, so it stops
   offering "link Google" to accounts that already have Google.
3. **Linked identities.** The Woo page gains the list of what is already
   attached, with its unlink control. Folding it in here rather than at 8.4 is
   deliberate: the section owns "what is linked and what may be linked", and
   splitting that across two sub-phases would leave one partial with two
   behaviours — the exact condition being removed.

Everything else must diff to whitespace.

## Not in scope

Layout, ordering, CSS, copy, field-state fixes. All of it is 8.4.

## Outcome

`Frontend\AccountForm` plus seven partials under `templates/partials/account/`.
The WooCommerce template went from 330 lines to 65, and every one of those 65 is
WooCommerce's own business: its nonce, its `save_account_details` field, and the
four hook points. `profile-summary.php` lost 80 lines to the same two partials,
which is what makes them single-owner rather than merely extracted.

phpcs: zero new violations across all ten new or changed files. The single error

### The diff, measured on the live page rather than reasoned about

The Local install was running the pre-8.2 code, so the "before" was captured from
the rendered page, stored in `localStorage` to survive the reload, and diffed
against the "after" on tag boundaries with nonces and generated ids normalised.

The result is exactly the declared deltas and nothing else:

| | Before | After |
| --- | --- | --- |
| Status notice | bare `Địa chỉ, Ngày sinh, Giới tính` | `<strong>Bạn có thể bổ sung thêm</strong>` + `<p>` |
| Provider buttons | two, including Google | one — Google is linked, so it is no longer offered |
| Linked identities | absent | `Cách đăng nhập của bạn` · Google · `1171••••••` |
| `password_current` | `autocomplete="new-password"` | `current-password` |

The last row is a fourth delta, not declared in advance: the `password-field`
partial derives `autocomplete` from `'password' === $name`, so the current
password box asked password managers to generate a new password into it. The fix
belonged wherever that partial's arguments were next touched, and that was here.

A fifth change has no visible diff on this account: the pending-contact notice
moved from mid-form into the status block, because one owner cannot render the
same notice in two positions. It is only reachable with a verification in flight.

On this account the new section also puts the Phase 6 orphan guard in front of a
person for the first time — Google is the only identity, so the row reads
`Không thể bỏ — đây là cách đăng nhập duy nhất` instead of offering an unlink
that would have been refused.

### The exclusion that was retired, and what it had been hiding

`woocommerce/form-edit-account` is now rendered by
`run-template-tests.php` — 73 assertions, up from 49. Until this sub-phase it sat
in the written-down exclusion list on the grounds that it needed a WooCommerce
runtime, which meant **the most complex template in the plugin had never been
executed by any test**. That is not a coincidental gap; it is where the drift
this whole phase exists to remove was free to accumulate.

### Three things the suites caught that reading would not have

- Moving markup broke two assertions in the 163-test regression suite, which
  greps template *source* for `data-sl-provider-mode="link"` and
  `name="smartlogin_referral_code"`. They now follow the markup to the partials
  that own it. The suite doing its job is the point.
- `profile-summary.php` kept a reference to `$sl_edit` after its definition moved
  into the renderer. PHP treats an undefined variable as null and `esc_url( null )`
  renders an empty href without complaint — the same silent-null failure mode the
  tracker records twice for `$default`/`$fallback`. The template smoke test failed
  on the notice.
- The status fixture now carries non-empty missing-field lists, which reached
  `wp_list_pluck()` for the first time and found it was never stubbed. The old
  fixture had both lists empty, so that branch had never run in any test.
